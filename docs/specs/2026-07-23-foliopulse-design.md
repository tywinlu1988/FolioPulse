## 一、项目定位

### 1.1 一句话定义

FolioPulse 是一款面向商业银行客户经理的 **AI 驱动的投资标的推荐引擎**，输入客户画像，输出结构化推荐列表及客户交付物料。

### 1.2 核心价值

| 维度 | 传统方式 | FolioPulse |
|------|---------|-----------|
| 产品筛选 | 客户经理手动翻阅产品库，依赖个人经验 | 规则过滤 + 多因子打分，覆盖全品类 |
| 适当性匹配 | 人工对照风险等级表，易遗漏 | 内置监管规则自动校验，逐笔留痕 |
| 客户沟通 | 口头推荐，无标准化材料 | 一键生成问答清单、话术清单、配置建议书 |
| 合规追溯 | 推荐过程不可回溯 | 回溯日志记录每一步决策，可复盘可审计 |

### 1.3 产品范围

全品类覆盖：公募基金（股票型/混合型/债券型/指数型/QDII）、A 股股票、ETF、REITs、可转债、银行理财产品。

### 1.4 部署形态

Claude Code / Codex 兼容的独立 CLI Skill，客户经理在终端中对话使用。

## 三、三阶段 Skill 链设计

### 3.1 S1：客户画像摄入（profile-intake）

**职责**：从自然语言中提取结构化客户画像，匹配画像模板

**4 问路由协议**（一次一问）：

| 问序 | 问题 | 选项 |
|------|------|------|
| Q1 | 客户的投资目标是什么？ | 资产增值 / 稳健收益 / 养老规划 / 子女教育 / 流动性管理 / 其他 |
| Q2 | 风险承受等级？ | R1（保守）/ R2（稳健）/ R3（平衡）/ R4（进取）/ R5（激进） |
| Q3 | 计划投资金额与期限？ | 金额（万元）+ 期限（短期<1年 / 中期1-3年 / 长期>3年） |
| Q4 | 是否有特殊约束？ | 行业偏好 / 禁投行业 / 流动性要求 / 其他 |

**输出（画像表 PS）**：

```yaml

risk_level: "R3"
amount: 500000        # 单位：元
horizon: "中期"
goal: "资产增值"
liquidity: "低"
constraints:
  - "不投军工"
  - "偏好消费行业"

risk_assessment_score: 3
investor_type: "合格投资者"

  - dev/engine/product-taxonomy.md

```

### 3.2 S2：推荐引擎（recommend-engine）

**职责**：按画像表执行推荐管道，输出推荐制品

**四步管道**：

```
Step 1: 规则过滤
  ├── 风险等级匹配过滤（R3 客户 → 排除 R4/R5 专属产品）
  ├── 投资期限匹配（中期 → 排除锁定期 > 3 年的产品）
  ├── 产品类型过滤（按画像约束排除）
  ├── 禁售/限售名单过滤
  └── 客户自定义约束过滤（行业偏好/禁投行业）

Step 2: 多因子打分
  ├── 股票因子：PE 分位 / PB 分位 / ROE / 营收增速 / 动量 / 波动率 / 股息率
  ├── 基金因子：Alpha / Beta / Sharpe / 最大回撤 / 规模 / 基金经理稳定性
  ├── ETF 因子：跟踪误差 / 流动性 / 费率 / 规模
  └── 理财产品因子：预期收益率 / 风险等级 / 发行机构评级 / 历史兑付率

Step 3: 双轨交叉验证
  ├── 轨 A（基本面）：财务数据、行业地位、治理评估
  └── 轨 B（市场信号）：资金流向、机构持仓变化、舆情情绪

Step 4: 排序 + 推荐理由生成
  ├── 综合加权排序
  ├── 每只产品生成 ≤ 3 条核心理由
  └── 组合层面：风险暴露分析 + 集中度提示
```

### 3.3 S3：推荐质检（recommend-qa）

**职责**：逐项校验推荐结果，生成质检判定

**6 项必检门禁**：

| 门禁 | 规则引用 | 不通过处理 |
|------|---------|-----------|
| 风险匹配 | suitability-rules.md §3 | 标记违规，降级或移除 |
| 禁售过滤 | filter-rules.md §4 | 直接移除 |
| 评分置信度 | scoring-framework.md §6 | 降置信度标识 |
| 数据完整性 | 回溯日志数据溯源表 | 标注缺失 |
| 评分可追溯 | 每一分可回溯到因子原始值 | 要求补全 |
| 理由合规 | 不含有承诺收益/夸大表述 | 重新生成 |

```

├── 标的报告-{名称1}.md   # 单只产品深度分析

├── 问答清单.md           # 预判客户问题 + 建议回答要点
├── 话术清单.md           # 沟通流程脚本
├── 配置建议书.md         # 正式资产配置方案
└── 回溯日志.md           # 过程透视（见第五章）
```

### 4.3 RM 调整交互

RM 在 CLI 中可以：

| 操作 | 示例 | 处理 |
|------|------|------|
| 替换产品 | "把第 3 只换成 000002" | 重新打分排序，更新推荐列表 |
| 调整配比 | "股票型降到 35%，混合型加到 40%" | 重算组合风险暴露 |
| 补充备注 | "第 1 只加备注：客户之前买过" | 写入 RA 和回溯日志的 RM 干预节 |
| 删除产品 | "去掉第 4 只" | 从列表移除，进入备选池 |
| 追加产品 | "看看备选池里有没有消费行业的 ETF" | 从备选池按条件召回 |

所有干预动作记录到回溯日志 §6。

## 五、模板设计

### 5.1 设计原则

- **纯净占位符**：所有字段为 `{字段名}` 形式，零示例数据，防止模型照抄
- **结构固定**：标题层级、表格列序、段落顺序固定，引擎只填值不调结构
- **可打印**：纯 Markdown，任意渲染器导出 PDF 即可交付客户

### 5.2 配色体系

| 要素 | 色值 | 用途 |
|------|------|------|
| 主色 — 藏蓝 | `#1A3A5C` | 标题、表格表头、重点区块边框 |
| 强调色 — 琥珀金 | `#B8860B` | 评分星级、关键数据高亮、分割线 |
| 信号色 — 森林绿 | `#2D6A4F` | 风险匹配通过、正面指标 |
| 信号色 — 暗珊瑚 | `#C85A4A` | 风险警示、负面指标、置信度低 |
| 中性色 — 暖灰 | `#8B8581` | 辅助文字、备注、数据缺失占位 |
| 底色 — 暖白 | `#FAF8F5` | 报告底色（打印友好） |

## 六、回溯日志设计

### 6.1 定位

回溯日志不是合规文档，而是**过程透视镜**。用途：
- **防过拟合**：检验模型是否只挑"好推"的产品而绕过边界情况
- **防幻觉**：每个数据点可追溯到适配器和获取时间
- **可复盘**：事后分析推荐质量，支撑引擎迭代
- **可审计**：区分模型输出与人工修正

## 八、数据架构

### 8.1 数据源分层

| 层级 | 数据内容 | 适配器 | 实时性 |
|------|---------|--------|--------|
| L1 行情 | 股价、净值、涨跌幅 | eastmoney | 实时/延迟 15 分钟 |
| L2 基本面 | PE/PB/ROE/财报 | eastmoney / tiantian | T+1 |
| L3 基金详情 | 持仓/规模/费率/经理 | tiantian | T+1~T+7 |
| L4 理财产品 | 预期收益/风险等级/历史兑付 | wind | 按发行周期 |
| L5 舆情 | 新闻/研报/公告情绪 | WebSearch | 实时 |

### 8.2 数据模式

| 模式 | 说明 | 触发条件 |
|------|------|---------|
| **Mode A** | 仅公开免费数据（东方财富、天天基金） | 默认 |
| **Mode B** | 用户提供的外部数据（Wind 终端、CSV 上载） | 用户主动指定 |

Mode B 护栏：QA 校验 Mode B 数据源是否经用户显式授权，未经授权不得出现外部数据值。

## 九、反漂移铁律

以下规则约束所有 Skill 和引擎的行为，不可逾越：

| 编号 | 铁律 | 说明 |
|------|------|------|
| R1 | **禁止自创产品分类** | 所有产品类型必须引用 `engine/product-taxonomy.md` |
| R2 | **禁止自定评分权重** | 所有因子权重必须引用 `engine/scoring-framework.md §section` |
| R3 | **禁止绕过适当性校验** | 每笔推荐须通过 `suitability_validator` 并记录匹配规则 |
| R4 | **禁止伪造数据** | 无数据来源的字段标注"数据缺失"，不编造 |
| R5 | **禁止偏离画像表** | S2 严格按 PS 参数执行，不得擅自扩大或缩小范围 |
| R6 | **禁止跳过质检** | 未经 QA 签章的推荐不得输出 |
| R7 | **单一真相源** | 任何数值阈值/权重只存在于 `dev/engine/` 文档中，Skill 和代码引用该文档段落 |
| R8 | **必录回溯** | 每次推荐必须生成完整回溯日志，无日志不交付 |
